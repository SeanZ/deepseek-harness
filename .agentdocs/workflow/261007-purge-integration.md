# dev 的 purge 集成与版本验收

## 目标

按用户 2026-10-07 指令，dev 保留 purge 集成、构建与脱敏测试补丁。新版先在本地完成构建和测试，再交付同一制品到 my43 隔离验收。推送目的地为 origin/dev（用户 fork），upstream 仅用于读取官方版本。现有本地未提交代理文档保留。

## 设计

核心回到已选定的官方版本，移除自有 request-injections 和 creative 实现。purge 固定源码提交与摘要，安装至独立构建运行时，不能对官方源码目录或当前生产 release 原位打补丁。复用官方 build:official/release:pack 和已验证的源码依赖闭包、pnpm 第三方补丁打包逻辑。

旧会话原件保留，迁移仅写新的输出目录；将旧注入事件保留为 ignorable 审计记录，退出旧请求重建语义。creative 仅在迁移 profile 中作为 standard 的无注入兼容别名。版本升级必须使用实际官方读取器验证历史、副本追加和重开；五个既有不可恢复会话单列，不自动修复。

purge 会修改运行时文件和权限默认值。补丁应用必须限制在独立运行时/home；记录实际匹配和缺失规则，不能将跳过视为成功。启动后的宿主自修改需纳入完整性与边界测试，保留可复现版本。

## 阶段

- [x] 确认 fork/dev、官方基线与未提交文件，保存原始改动副本。
- [x] 退出旧核心实现，建立固定版本集成和官方构建打包入口。
- [x] 构造脱敏回归并通过本地构建、类型、lint、文档与持久化/真实入口检查。
- [ ] 提交并推送 origin/dev，回读远端提交。
- [ ] 上传同一制品到 my43；独立 home/port 验证新会话、旧历史、配置、真实模型和重启。
- [ ] 更新长期维护约束，等待人工验收；确认无其他改动后归档。

## 验收数据

盘点快照有 105 个会话，100 个可恢复；10 个会话含 13 条旧注入事件，6 个引用 creative。仓库仅写合成文本、虚拟 ID/路径和非敏感模型标识，禁止复制真实内容、凭据或个人路径。真实副本只在权限受限的忽略目录中验证。

## 本地门禁

官方构建完成；完整集成流程在新的临时目录安装 291 个包，校验 6414 个文件。19 项制品/平台测试通过，一次性旧格式导出覆盖 V0–V4 与分叉；核心定向回归 1945 项通过、1 项既有跳过，仓库引用门禁 12 项通过。doc-sync 42 项通过，仓库及 MJS 专项 lint、语法和 Prettier 检查通过。Apple Git 2.39 不支持门禁测试所需 GIT_NO_LAZY_FETCH，使用已安装 Git 2.52 验证通过。

固定 Web 规则为 59 applied、7 already、2 missing_file、2 na。purge 路径识别不接受包含 deepseek-harness 的 Web 运行时；构建在系统临时目录应用并将文件封存回跨平台原始 tarball。macOS 的 /var 与 /private/var 用 realpath 比较。启动后延迟自愈窗口结束，制品字节仍相同。
